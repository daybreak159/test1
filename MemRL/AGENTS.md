# MemRL开发和实验约定

## GitHub 源码同步范围

- 本目录是 coding 源码的筛选同步版：保留完整 src、8 个正式脚本和必要工程文件。
- 不跟踪 tests、baselines、部署辅助脚本、外部 configs/使用说明软链接、数据、权重或运行产物。
- 开发调试、临时构建和一次性脚本放 `_dev/`；仅 `_dev/README.md` 入库。
- 下列绝对路径、发布包和路径解析工具的约定适用于 coding 原部署，不表示这些文件随本仓库提供。
- 不因修改同步仓库而移动、删除 coding 中的原始实验文件。未执行的测试、API、反向或更新不得宣称通过。

## coding 原部署约定

- coding项目根目录为`/home/ubuntu/coding/MemRL`，仅保留`01_部署与配置`、`02_源码与脚本`、`03_实验结果`三类。
- 唯一开发源码在`02_源码与脚本`；修改前先查看Git状态，保护现有修改。使用Git记录版本，不复制整目录备份，不维护另一份共享源码。
- `configs`和`使用说明.md`指向`01_部署与配置`中的唯一配置和文档。修改配置属于实验协议变更；不要修改既有运行目录的配置和原始证据。
- 当前E/U/R只使用HF；保持e-text-v1。按用户2026-10-15明确要求，默认方法三：KV cache开启、policy_loss=single_step_pg、每批各优化器仅step一次。behavior_tolerance=0.03仅作为有限概率差异的日志阈值，不阻止默认PG更新；非有限数值、过期版本、梯度隔离等仍拒绝。显式policy_loss=ppo可回到严格旧方案；不恢复旧vLLM后端或混合修正。
- 所有新任务流使用`bash scripts/memrl.sh`。默认启动验收；正式训练必须显式`--train`。仅做测试或整理文件的请求不授权启动下一轮正式实验。
- 新运行统一写入`03_实验结果/runs`，使用独立名称；诊断写入`03_实验结果/diagnostics`。不得在coding根目录、源码目录或个人临时目录持续写结果。
- 默认SFT初始化权重在`03_实验结果/checkpoints/E文本SFT30_RL初始化权重`。SFT权重导入是新优化器/游标/记忆库，不是RL断点续训。
- 启动时记录完整生效配置、数据hash、源码Git提交及core hash、权重来源、命令和结果目录。结果索引只报告实际发生的步骤，不把启动通过写成参数更新成功。
- GPU0运行Solver，GPU1训练；不要停止别人的模型服务、改现有venv依赖、无检查覆盖端口。环境桥可按本轮配置启动并只清理自己启动的进程。
- 可复用脚本才进入scripts；一次性迁移/修补脚本放临时目录，完成后删除。保留结论、操作清单和验收报告，不把一次性脚本变成新启动入口。
- 历史结果中的旧路径通过`03_实验结果/path_map.json`或`scripts/resolve_artifact.py`解析，禁止批量改写轨迹、判题证据、checkpoint manifest及协议hash。
- 修改后运行与变更有关的测试；发布前从压缩包解压测试。交付包仅由`scripts/package_source_handoff.py`生成到releases/current，每次替换前验证，旧包使用Git版本追溯，不堆积.bak。
- 源码测试、API调用、环境工具、长输入反向、完整RL更新分开报告。32K+1反向通过不证明32K长输出或所有token概率都通过。
